# Reporting a security concern

Do not post credentials, private memories, conversation logs or authentication
files in a public issue.

If this repository offers **Security → Report a vulnerability**, use that
private GitHub form. If it is unavailable, open a minimal issue asking the
maintainer for a private reporting channel, without exploit details or private
data. No dedicated security email address has been announced.

Include the affected release and a minimal reproduction using synthetic data
when a private channel is available.

This project is a research preview maintained by Jonathan Pacifico. There is no promised
response-time agreement or declared long-term support branch. Older release
artifacts are kept for recovery, not as a claim of ongoing security maintenance.

Memory is stored locally, but the selected remote model provider receives
the context needed for responses and maintenance. Keep that distinction in mind
when deciding what information to use during testing.
